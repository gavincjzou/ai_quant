## 🔄 阶段8 Fix Round 2（00:15 深夜补修）

### 问题发现
复盘时 Gavin 发现企业微信**没有收到平仓告警**，查日志验证。

### 根因
告警代码只在 `Orchestrator.scan/monitor` 里，`manual_close_positions.py` 直接调 `trader.execute_signal` 绕过了。

### 修复方案：告警下沉到 PaperTrader

**架构变更**：
```
之前：
  Orchestrator.scan
    ├─ trader.execute_signal
    └─ alerter.info(...)  ← 只在这里

之后：
  Orchestrator.scan
    └─ trader.execute_signal
         ├─ 下单 / 更新状态 / 写 DB
         └─ _fire_trade_alert()  ← 下沉到这里
```

**代码变更**：
- `PaperTrader.__init__` 接受 `alerter` 参数
- 新增 `PaperTrader._fire_trade_alert()` 方法（智能分级）
  - BUY → INFO 🟢
  - SELL（策略）→ INFO 🔴
  - SELL（风控止损/TP）→ WARNING 🛡
  - SELL（manual_close）→ WARNING ✋
- `Orchestrator.scan/monitor` 移除重复告警（避免双推送）
- `manual_close_positions.py` 也传 alerter

### 补发遗漏

手动补发了 2 条 markdown：
- 3 笔 SELL（AAPL/AMZN/GOOGL，$239 滑点+手续费合计）
- 3 笔 BUY（META/TSM/AVGO，新 Momentum 建仓）

### 学到的

> **所有"副作用/通知"逻辑应该下沉到产生副作用的层**，而不是依赖调用方自觉发通知。否则任何新脚本/新路径都是告警遗漏风险。

这条要加入"系统设计原则"。

# 2026-04-27 周一复盘

## 主线

发现 launchd 时间设置有 bug，导致 Paper Trading 自 04-25 之后 **3 天没真正跑过新数据**，紧急修复。

## 已完成

### 🐛 故障诊断

**症状**：
- launchd 显示加载正常，周日/周一 21:30 也跑了
- 但 `last_scan_date` 一直停留在 2026-04-24
- factor_snapshots 也只有 04-25 一份 V1 快照
- daily_performance 4-23/24/25 三天都是相同总资产

**根因**：
- launchd 配置：北京时间 21:30 触发
- **北京 21:30 = 美东 09:30**（早盘开盘期）
- `last_closed_trading_day()` 返回的是**前一天**（最近已收盘日）
- 上次跑过了 → `target ≤ last_scan` → skipped → 永远 0 gap 空转

**影响**：
- Paper Trading 没真正跑策略 / 下单
- V1 因子从未自动跑过（因为 `has_processed > 0` 才触发）
- Dashboard 数据停留在 04-25
- 企微推送一直推"无需补跑"，无信息量

### ⚙️ 修复方案

**改时间策略：北京 21:30 → 北京 08:00**

| 北京时间 | 美东时间（夏令）| 美股状态 |
|---------|---------------|---------|
| 21:30 ❌ 旧 | 09:30 当天 | 早盘开盘 |
| **08:00 ✅ 新** | **20:00 前一天** | **收盘 4h，最稳** |

夏冬令时切换都安全（冬令时美东 19:00 也是盘后）。

**心跳推送增强**：

0 gap 时除了"无需补跑"，新增：
- 美东 + 北京双时间
- 总资产 / 现金 / 持仓市值
- 持仓 Top-5 按浮盈倒序
- 下次运行预告

## 反思

**踩坑教训**：
1. 部署 launchd 时**没考虑时区换算**——只看到"21:30"觉得是晚上够晚，没想美股周期
2. 周末跑 + 工作日早盘跑都是 0 gap，**如果不主动诊断永远不会发现**
3. **心跳消息不能简陋**——"无需补跑"5 个字让用户产生"系统在跑"的错觉，实际啥也没做

**正确原则**：
- 依赖外部数据源的定时任务必须**用数据源时区算触发时间**
- 心跳消息要包含**真实状态**（持仓/资产），不能只说"我活着"
- 任何跨时区的 datetime 处理必须用 pytz，**不要硬编码 UTC offset**
